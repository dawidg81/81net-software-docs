Minecraft Classic 0.30 server

dawidg81 in 2026.09.03

We will make a Minecraft Classic c0.30 server software.

Such server software should handle basic information on world data, player position and chat. It runs most of the game logic while the client (c0.30, ClassiCube) handles displaying everything graphically, calculating player movement, etc.

We can see that the server relatively doesn't need much to handle whole game. Such universality and extensibility allows us to implement any mini-game/gamemode that fits into the voxel engine environment. The most popular gamemode implemented into many server softwares of such type is of course creative or survival.

Networking

Since our program will act as a server, we need to make the running program to be accessible for the game client. It means that clients can connect to the server by knowing the address and the port number of the running server.

The port number is a special socket number the server needs to listen to to let clients connect to it. The port can also help with recognization of a service the server is providing. If you was ever making a Minecraft server, in cloud (e.g. Aternos) or locally, you may know that the default port for Minecraft servers is 25565.

The first thing that our server should do is to create a special socket file descriptor (Linux) then attach it to our port 25565 and finally listen to it. After all of that, our server is ready and only waiting to accept incoming connection from the client and send and receive data from and to it.

Greeting a new client

After the server sees an incoming connection from the client and creates a client socket variable on its side, it is ready to send and receive data from the client. After the Minecraft client connects to the server it waits until the server will send specific data. The first thing our server needs to do after connecting with client is sending information on protocol version, server name, server Message Of The Day and information whether the player is an admin or not.
